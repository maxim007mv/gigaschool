# 1. Назначение

Документ задаёт физическую модель данных КАРКАС. Схема оптимизирована под три критичные операции: (1) живой пересчёт и проверка часов каркаса за миллисекунды, (2) проверка покрытия «результат обучения → темы → оценочные средства», (3) точечная пересборка элементов комплекта по графу связей. Все DDL-скрипты из раздела 5 применены к чистой базе и прогнаны на демонстрационных данных; результаты приведены в разделах 11–12.

# 2. Принципы моделирования

| **Принцип** | **Реализация** | **Зачем** |
|:---|----|----|
| Часы хранятся только на листовом уровне | topic_workload (topic_id, activity, mode, hours); итоги — представления v_topic_hours, v_module_hours, v_program_hours | Невозможно рассогласование «итоговая строка ≠ сумме строк», найденное в образце АЦР на 248 ч |
| Связи ЗУН — явные таблицы M:N | topic_outcome, assessment_outcome | Покрытие проверяется одним SQL-запросом (v_outcome_coverage) |
| Стабильные ref | Столбец ref с CHECK-шаблоном (C1, LO1.2, M2, T2.3) и UNIQUE (program_id, ref) | Точечные правки, diff версий, ссылки из отчёта |
| Рабочее состояние + неизменяемые снимки | Нормализованные таблицы = текущий черновик; program_version.snapshot (JSONB, KitV1) — неизменяемый снимок на каждом шаге | Быстрая правка + полная история, откат, сравнение |
| Реестры отдельно от программ | normative_act, prof_standard, labor_function, service_catalog | Код или номер попадает в программу только по внешнему ключу на запись реестра |
| Human Gate на уровне БД | Триггер program_gate: утверждение только при сходящихся часах и с утверждающим; kit_generating только после утверждения | Защита от обхода UI/API |
| Одна СУБД для всего | Очередь job (SKIP LOCKED), кэш llm_cache, векторы kb_chunk.embedding | Минимум компонентов, транзакционная согласованность |

<p>-- ---------- Представления: часы считаются, а не хранятся -----------------</p>
<p>CREATE VIEW v_topic_hours AS</p>
<p>SELECT t.program_id, t.module_id, t.id AS topic_id, t.ref,</p>
<p>coalesce(sum(w.hours) FILTER (WHERE w.activity = 'lecture'), 0)::int AS lecture,</p>
<p>coalesce(sum(w.hours) FILTER (WHERE w.activity = 'practice'), 0)::int AS practice,</p>
<p>coalesce(sum(w.hours) FILTER (WHERE w.activity = 'lab'), 0)::int AS lab,</p>
<p>coalesce(sum(w.hours) FILTER (WHERE w.activity = 'self_study'), 0)::int AS self_study,</p>
<p>coalesce(sum(w.hours) FILTER (WHERE w.activity = 'current_control'), 0)::int AS control,</p>
<p>coalesce(sum(w.hours) FILTER (WHERE w.mode = 'distance'), 0)::int AS distance,</p>
<p>coalesce(sum(w.hours), 0)::int AS total</p>
<p>FROM topic t LEFT JOIN topic_workload w ON w.topic_id = t.id</p>
<p>GROUP BY t.program_id, t.module_id, t.id, t.ref;</p>
<p>CREATE VIEW v_module_hours AS</p>
<p>SELECT m.program_id, m.id AS module_id, m.ref, m.number,</p>
<p>coalesce(sum(h.lecture),0)::int AS lecture, coalesce(sum(h.practice),0)::int AS practice,</p>
<p>coalesce(sum(h.lab),0)::int AS lab, coalesce(sum(h.self_study),0)::int AS self_study,</p>
<p>coalesce(sum(h.control),0)::int AS control, coalesce(sum(h.distance),0)::int AS distance,</p>
<p>coalesce(sum(h.total),0)::int AS total</p>
<p>FROM module m LEFT JOIN v_topic_hours h ON h.module_id = m.id</p>
<p>GROUP BY m.program_id, m.id, m.ref, m.number;</p>
<p>CREATE VIEW v_program_hours AS</p>
<p>SELECT p.id AS program_id, p.total_hours AS requested, p.final_att_hours,</p>
<p>coalesce(sum(mh.lecture),0)::int AS lecture, coalesce(sum(mh.practice),0)::int AS practice,</p>
<p>coalesce(sum(mh.lab),0)::int AS lab, coalesce(sum(mh.self_study),0)::int AS self_study,</p>
<p>coalesce(sum(mh.control),0)::int AS control,</p>
<p>(coalesce(sum(mh.total),0) + p.final_att_hours)::int AS grand_total</p>
<p>FROM program p LEFT JOIN v_module_hours mh ON mh.program_id = p.id</p>
<p>GROUP BY p.id, p.total_hours, p.final_att_hours;</p>
<p>-- Покрытие: каждый результат обучения ≥ 1 тема и ≥ 2 оценочных средства</p>
<p>CREATE VIEW v_outcome_coverage AS</p>
<p>SELECT lo.program_id, lo.id AS outcome_id, lo.ref, lo.type,</p>
<p>(SELECT count(*) FROM topic_outcome tl WHERE tl.outcome_id = lo.id) AS topics,</p>
<p>(SELECT count(*) FROM assessment_outcome ao WHERE ao.outcome_id = lo.id) AS assessments</p>
<p>FROM learning_outcome lo;</p>
<p>-- ---------- Функция проверки часов (V-HRS) ------------------------------</p>
<p>-- Возвращает пустой набор, если всё сходится; иначе — список нарушений.</p>
<p>CREATE OR REPLACE FUNCTION check_program_hours(p_program uuid)</p>
<p>RETURNS TABLE (rule_code text, entity_ref text, message text)</p>
<p>LANGUAGE sql STABLE AS $$</p>
<p>SELECT 'V-HRS-01', NULL::text,</p>
<p>format('Сумма часов %s ≠ запрошенному объёму %s', ph.grand_total, ph.requested)</p>
<p>FROM v_program_hours ph</p>
<p>WHERE ph.program_id = p_program AND ph.grand_total IS DISTINCT FROM ph.requested</p>
<p>UNION ALL</p>
<p>SELECT 'V-HRS-02', t.ref, format('У темы %s нет часов', t.ref)</p>
<p>FROM v_topic_hours t WHERE t.program_id = p_program AND t.total = 0</p>
<p>UNION ALL</p>
<p>SELECT 'V-HRS-03', m.ref, format('В модуле %s нет тем с часами', m.ref)</p>
<p>FROM v_module_hours m WHERE m.program_id = p_program AND m.total = 0</p>
<p>UNION ALL</p>
<p>SELECT 'V-HRS-04', NULL,</p>
<p>format('Только самостоятельная работа (стажировка), но найдено ЛК/ПР/ЛБ: %s ч', ph.lecture + ph.practice + ph.lab)</p>
<p>FROM v_program_hours ph JOIN program p ON p.id = ph.program_id</p>
<p>WHERE ph.program_id = p_program AND (p.constraints-&gt;&gt;'self_study_only')::boolean</p>
<p>AND ph.lecture + ph.practice + ph.lab &gt; 0</p>
<p>UNION ALL</p>
<p>SELECT 'V-HRS-05', NULL,</p>
<p>format('Практика %s ч меньше минимума %s%% от объёма', ph.practice + ph.lab, p.constraints-&gt;&gt;'min_practice_share_pct')</p>
<p>FROM v_program_hours ph JOIN program p ON p.id = ph.program_id</p>
<p>WHERE ph.program_id = p_program AND p.constraints ? 'min_practice_share_pct'</p>
<p>AND (ph.practice + ph.lab) * 100 &lt; (p.constraints-&gt;&gt;'min_practice_share_pct')::numeric * ph.requested;</p>
<p>$$;</p>
<p>-- Human Gate на уровне БД: нельзя утвердить каркас с ошибками часов</p>
<p>CREATE OR REPLACE FUNCTION trg_program_gate() RETURNS trigger LANGUAGE plpgsql AS $$</p>
<p>BEGIN</p>
<p>IF NEW.status = 'framework_approved' AND OLD.status IS DISTINCT FROM 'framework_approved' THEN</p>
<p>IF EXISTS (SELECT 1 FROM check_program_hours(NEW.id)) THEN</p>
<p>RAISE EXCEPTION 'HOURS_MISMATCH: каркас нельзя утвердить, часы не сходятся'</p>
<p>USING ERRCODE = 'check_violation';</p>
<p>END IF;</p>
<p>IF NEW.approved_by IS NULL THEN</p>
<p>RAISE EXCEPTION 'APPROVER_REQUIRED' USING ERRCODE = 'check_violation';</p>
<p>END IF;</p>
<p>END IF;</p>
<p>-- генерация содержания возможна только после утверждения</p>
<p>IF NEW.status = 'kit_generating' AND OLD.status NOT IN ('framework_approved','kit_review') THEN</p>
<p>RAISE EXCEPTION 'GATE_NOT_PASSED: генерация комплекта до утверждения каркаса запрещена'</p>
<p>USING ERRCODE = 'check_violation';</p>
<p>END IF;</p>
<p>NEW.updated_at := now();</p>
<p>NEW.lock_version := OLD.lock_version + 1;</p>
<p>RETURN NEW;</p>
<p>END $$;</p>
<p>CREATE TRIGGER program_gate BEFORE UPDATE ON program FOR EACH ROW EXECUTE FUNCTION trg_program_gate();</p>
<p>-- Изменение часов/структуры после утверждения возвращает программу в framework_review</p>

<p>WHERE id = v_prog AND status IN ('framework_approved','kit_review');</p>
<p>RETURN NULL;</p>
<p>END $$;</p>
<p>CREATE TRIGGER workload_reopen AFTER INSERT OR UPDATE OR DELETE ON topic_workload</p>
<p>FOR EACH ROW WHEN (current_setting('karkas.solver', true) IS DISTINCT FROM 'on')</p>

<p>-- Снимки версий неизменяемы</p>

# 8. Секционирование и хранение

- llm_call и audit_log — RANGE-секции по месяцам (created_at), DEFAULT-секция страхует от отсутствия секции. Новые секции создаёт ежедневная задача maintenance.partitions на 2 месяца вперёд; удаление старых — DROP TABLE секции (мгновенно, без VACUUM) по политике хранения 12 месяцев.

- Таблицы программ не секционируются: даже программа на 500 ч — это ≈ 150 тем, ≈ 600 строк часов и ≈ 1000 оценочных средств; все запросы идут по program_id через индексы.

- program_version.snapshot (JSONB 0,2–2 МБ) хранится в TOAST со сжатием (ALTER TABLE program_version ALTER COLUMN snapshot SET COMPRESSION lz4 на PostgreSQL 16+).

- Файлы и артефакты — в Object Storage; в БД только метаданные и S3-ключи.

- llm_cache очищается задачей по expires_at (индекс llm_cache_exp).

# 9. Кэширование

| **Уровень** | **Что кэшируется** | **Инвалидация** |

| Снимок каталога PyPI | Версии библиотек на дату | 24 ч; дата снимка показывается в отчёте |

**Гибридный поиск: вектор + полнотекст + RRF**

<th><p>-- :q_vec — эмбеддинг запроса (Qwen3-Embedding), :q_text — текст запроса</p>
<p>WITH vec AS (</p>
<p>SELECT id, 1 - (embedding &lt;=&gt; :q_vec) AS score FROM kb_chunk</p>
<p>WHERE org_id = :org ORDER BY embedding &lt;=&gt; :q_vec LIMIT 40),</p>
<p>txt AS (</p>
<p>SELECT id, ts_rank(tsv, plainto_tsquery('russian', :q_text)) AS score FROM kb_chunk</p>
<p>WHERE org_id = :org AND tsv @@ plainto_tsquery('russian', :q_text) LIMIT 40)</p>
<p>SELECT c.id, c.heading_path, c.content,</p>
<p>coalesce(1.0/(60 + v.rnk), 0) + coalesce(1.0/(60 + t.rnk), 0) AS rrf -- Reciprocal Rank Fusion</p>
<p>FROM kb_chunk c</p>
<p>LEFT JOIN (SELECT id, row_number() OVER (ORDER BY score DESC) rnk FROM vec) v USING (id)</p>
<p>LEFT JOIN (SELECT id, row_number() OVER (ORDER BY score DESC) rnk FROM txt) t USING (id)</p>
<p>WHERE v.id IS NOT NULL OR t.id IS NOT NULL</p>
<p>ORDER BY rrf DESC LIMIT 12; -- далее реранкер Qwen3-Reranker → top-5 в контекст навыка</p></th>
