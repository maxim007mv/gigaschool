# 1. Назначение

Документ описывает серверную часть КАРКАС: как устроены модули, какие навыки выполняет агент, по каким правилам принимаются решения (выбор шаблона, уточнения, часы, профстандарты, источники, самопроверка, точечные правки), полный контракт REST API и порядок тестирования. |:---|----|----|
| «повышение квалификации», «ДПП», «стажировка», «удостоверение», работники/специалисты/учителя/госслужащие | dpp_pk | сильный |

Таблица 4.2 — Правила выбора шаблона

Правила дают оценку уверенности; при конфликте сильных признаков или уверенности \< 0,8 решение принимает LLM-арбитр с обоснованием, а при отсутствии признаков формируется вопрос. Выбор всегда показывается методисту и может быть изменён (US-2). Переключатель режима «шаблоны АЦР / база знаний организации» реализуется через kb_document.doc_role = template (ОТЧ-11, ОТЧ-12).

## 5.2. Уточняющие вопросы (S03)

| **Слот** | **Обязателен** | **Если не задан** | **Пример формулировки** |
|:---|----|----|----|
| kind (тип программы) | да | вопрос | Какой это тип программы: повышение квалификации или общеразвивающая? |
| total_hours (объём) | да | вопрос; «примерно месяц» не считается объёмом | Сколько всего академических часов? Например, 36, 72 или 144 |
| audience (слушатели) | да | вопрос | Кто будет учиться? |
| entry_level (входной уровень) | да | вопрос | Что слушатели уже умеют? |
| form (форма обучения) | да | вопрос | Как будут проходить занятия: очно, очно-заочно, дистанционно? |
| final_attestation | да | вопрос | Как проверить результат в конце? |
| schedule (срок, ч/день) | нет | по умолчанию из шаблона; записывается в допущения | — |

Таблица 4.3 — Слоты уточнения

- Вопросов не больше 5 (CHECK в БД); если не хватает больше 5 слотов — объединяются наименее важные (форма + срок) либо берутся значения по умолчанию с записью в допущения.

- Формулировки без технического жаргона; у каждого вопроса — варианты-кнопки и пояснение «зачем».

- Ответ «на ваше усмотрение» (как в тест-кейсе 4) → значение по умолчанию для вида программы и аудитории, clarification.is_default = true, пункт в assumptions и в отчёте.

- Пока обязательные слоты пусты, framework:generate возвращает 409 CLARIFICATION_REQUIRED — агент не додумывает (ТК4-1).

## 5.3. Профстандарт и трудовые функции (S05)

**1.** Только для dpp_pk; для dop шаг пропускается, а V-TPL-02 запрещает ссылки на профстандарты (ТК1-9).

**2.** Если профстандарт приложен (например, «Педагог» в ТК-2) — его код и ТФ извлекаются из файла и сверяются с реестром.

**3.** Иначе — кандидаты из реестра: pg_trgm по названию + векторный поиск по описаниям ТФ (топ-10).

**4.** LLM ранжирует **только кандидатов** и выбирает ТФ; выход проверяется: код ∈ кандидатам, статус active.

**5.** Если подходящего нет — поле остаётся пустым с пометкой «требуется выбор методиста»; на экране — поиск по реестру (/registry/prof-standards).

<p>from dataclasses import dataclass, field</p>

<p>@dataclass</p>
<p>class TopicIn:</p>
<p>ref: str</p>
<p>weight: float = 1.0</p>
<p>practicality: float = 0.5 # 0 — теория, 1 — практика</p>

<p>ref: str</p>
<p>weight: float</p>

<p>@dataclass</p>
<p>class Constraints:</p>
<p>total: int # запрошенный объём, ч</p>
<p>final_att: int = 2 # итоговая аттестация, ч</p>
<p>unit: int = 1 # кратность часов темы (2 — «пары» в школе)</p>
<p>self_study_only: bool = False # стажировка без аудиторных занятий</p>
<p>min_practice_share: float = 0.0 # доля ПР+ЛБ от общего объёма</p>
<p>self_study_share: float = 0.0 # доля СРС (очно-заочная форма)</p>
<p>distance_share: float = 0.0 # доля дистанционных часов от контактной работы</p>
<p>@dataclass</p>
<p>class Plan:</p>
<p>rows: dict[str, dict[str, int]] = field(default_factory=dict) # T-ref → часы по видам</p>
<p>distance: dict[str, int] = field(default_factory=dict) # T-ref → дистанционные часы</p>
<p>module_of: dict[str, str] = field(default_factory=dict)</p>
<p>proof: list[tuple[str, bool, str]] = field(default_factory=list) # (правило, ок, пояснение)</p>
<p>def largest_remainder(total: int, weights: list[float], mins: list[int]) -&gt; list[int]:</p>
<p>"""Целочисленное распределение total пропорционально weights с нижними границами (метод Гамильтона)."""</p>
<p>if sum(mins) &gt; total:</p>
<p>raise HoursInfeasible(f"Минимальные часы ({sum(mins)}) больше доступных ({total})")</p>
<p>free = total - sum(mins)</p>
<p>s = sum(weights) or 1.0</p>
<p>quotas = [free * w / s for w in weights]</p>
<p>base = [floor(q) for q in quotas]</p>
<p>rest = free - sum(base)</p>
<p># стабильная сортировка: по остатку, затем по порядку — детерминизм</p>
<p>order = sorted(range(len(weights)), key=lambda i: (-(quotas[i] - base[i]), i))</p>
<p>for i in order[:rest]:</p>
<p>base[i] += 1</p>
<p>return [b + m for b, m in zip(base, mins)]</p>
<p>def solve(modules: list[ModuleIn], c: Constraints) -&gt; Plan:</p>
<p>content = c.total - c.final_att</p>
<p>if content &lt;= 0 or content % c.unit:</p>
<p>raise HoursInfeasible(f"{content} ч содержания не делится на кратность занятия {c.unit} ч")</p>
<p>units = content // c.unit</p>
<p>n_topics = sum(len(m.topics) for m in modules)</p>
<p>if n_topics &gt; units:</p>
<p>raise HoursInfeasible(f"Тем ({n_topics}) больше, чем занятий по {c.unit} ч ({units}) — объедините темы")</p>
<p>plan = Plan()</p>
<p># Шаг 1–2: модули и темы (в единицах кратности)</p>
<p>m_units = largest_remainder(units, [m.weight for m in modules], [len(m.topics) for m in modules])</p>
<p>for m, mu in zip(modules, m_units):</p>
<p>t_units = largest_remainder(mu, [t.weight for t in m.topics], [1] * len(m.topics))</p>
<p>for t, tu in zip(m.topics, t_units):</p>
<p>h = tu * c.unit</p>
<p>plan.module_of[t.ref] = m.ref</p>
<p>if c.self_study_only:</p>
<p>plan.rows[t.ref] = {"lecture": 0, "practice": 0, "lab": 0, "self_study": h}</p>
<p>continue</p>
<p># Шаг 3: разбиение темы по видам работ</p>
<p>srs = round(h * c.self_study_share)</p>
<p>contact = h - srs</p>
<p>pr_share = min(0.9, max(0.1, 0.25 + 0.6 * t.practicality))</p>
<p>lab = round(contact * 0.25) if t.has_lab else 0</p>
<p>pr = round((contact - lab) * pr_share)</p>
<p>lk = contact - lab - pr</p>
<p>plan.rows[t.ref] = {"lecture": lk, "practice": pr, "lab": lab, "self_study": srs}</p>
<p># Шаг 4: ремонт глобальной доли практики (детерминированно: по убыванию практичности)</p>
<p>need = ceil(c.min_practice_share * c.total) - sum(r["practice"] + r["lab"] for r in plan.rows.values())</p>
<p>by_pract = sorted((t for m in modules for t in m.topics), key=lambda t: (-t.practicality, t.ref))</p>
<p>while need &gt; 0:</p>
<p>donor = next((t for t in by_pract if plan.rows[t.ref]["lecture"] &gt; 0), None)</p>
<p>if donor is None:</p>
<p>raise HoursInfeasible("Нельзя набрать требуемую долю практики: лекционных часов для переноса не осталось")</p>
<p>plan.rows[donor.ref]["lecture"] -= 1; plan.rows[donor.ref]["practice"] += 1; need -= 1</p>
<p># Дистанционная часть: лекции тем с наименьшей практичностью → ДОТ</p>
<p>dist_need = round(c.distance_share * sum(r["lecture"] + r["practice"] + r["lab"] for r in plan.rows.values()))</p>
<p>for t in sorted((t for m in modules for t in m.topics), key=lambda t: (t.practicality, t.ref)):</p>
<p>take = min(dist_need, plan.rows[t.ref]["lecture"]); plan.distance[t.ref] = take; dist_need -= take</p>
<p>if dist_need &gt; 0:</p>
<p>raise HoursInfeasible("Доля дистанционных часов больше объёма лекций; уточните, какие практики идут дистанционно")</p>
<p>_prove(plan, modules, c)</p>
<p>return plan</p>
<p>def _prove(plan: Plan, modules: list[ModuleIn], c: Constraints) -&gt; None:</p>
<p>rows = plan.rows</p>
<p>tot = {a: sum(r[a] for r in rows.values()) for a in ACTS}</p>
<p>grand = sum(tot.values()) + c.final_att</p>
<p>P = plan.proof.append</p>
<p>P(("V-HRS-01 Σ строк + ИА = объём", grand == c.total, f"{sum(tot.values())} + {c.final_att} = {grand} (запрошено {c.total})"))</p>
<p>P(("V-HRS-06 Σ видов работ = итог строки", all(sum(r.values()) &gt; 0 for r in rows.values()), "по каждой теме"))</p>
<p>for m in modules:</p>
<p>s = sum(sum(rows[t.ref].values()) for t in m.topics)</p>
<p>P((f"V-HRS-07 Σ тем = модуль {m.ref}", s &gt; 0, f"{s} ч"))</p>
<p>if c.self_study_only:</p>
<p>P(("V-HRS-04 ЛК/ПР/ЛБ = 0 (стажировка)", tot["lecture"] + tot["practice"] + tot["lab"] == 0,</p>
<p>f"ЛК {tot['lecture']}, ПР {tot['practice']}, ЛБ {tot['lab']}, СРС {tot['self_study']}"))</p>
<p>if c.min_practice_share:</p>
<p>P(("V-HRS-05 доля практики", tot["practice"] + tot["lab"] &gt;= ceil(c.min_practice_share * c.total),</p>
<p>f"{tot['practice'] + tot['lab']} ч ≥ {ceil(c.min_practice_share * c.total)} ч"))</p>
<p>if any(r % c.unit for r in (sum(x.values()) for x in rows.values())):</p>
<p>P(("V-HRS-08 кратность занятия", False, f"часы тем не кратны {c.unit}"))</p>
<p>for rule, ok, msg in plan.proof:</p>
<p>if not ok:</p>
<p>raise HoursInfeasible(f"{rule}: {msg}")</p>
<p>def calendar(plan: Plan, c: Constraints, max_per_day: int, days_per_week: int) -&gt; list[tuple[int, int, str, int]]:</p>
<p>"""Раскладка часов по дням: (неделя, день, T-ref|ИА, часы). Не превышает max_per_day."""</p>
<p>out, day, left = [], 1, max_per_day</p>
<p>queue = [(ref, sum(r.values())) for ref, r in plan.rows.items()] + [("ИА", c.final_att)]</p>
<p>for ref, h in queue:</p>
<p>while h &gt; 0:</p>
<p>if ref == "ИА" and left &lt; c.final_att and left != max_per_day: # ИА не дробим</p>
<p>day += 1; left = max_per_day</p>
<p>take = min(h, left)</p>
<p>out.append(((day - 1) // days_per_week + 1, day, ref, take))</p>
<p>h -= take; left -= take</p>
<p>if left == 0:</p>
<p>day += 1; left = max_per_day</p>
<p>return out</p></th>

## 5.5. Календарный учебный график (S09)

Раскладывает часы тем по дням с ограничением «не более N часов в день» и числом учебных дней в неделю; итоговая аттестация не дробится. Для ТК-1 это 8 занятий по 2 ч за 4 недели, для ТК-5 — 64 дня по ≤ 4 ч (≈ 2 месяца), что совпадает с требованиями чек-листов. Для ДПП календарные даты не проставляются («формируется по мере комплектования групп», как в образце АЦР) — в графике указываются недели и дни.

## 5.6. Генерация содержания (S11–S17)

- **Контекстный паспорт темы**: РО темы, соседние темы модуля (чтобы не повторять материал), глоссарий программы, профиль аудитории (возраст, входной уровень), ограничения (сервисы, доступные в РФ; обезличенные данные), фрагменты RAG.

- **Порядок**: S11 (модуль) → параллельно по темам: S12 → S13, S14, S15; затем S16 (контроль/ИА) и S17 → S18 (источники).

- **Оценочные средства** генерируются строго с outcome_refs; для каждого РО — минимум 2 средства (тест + задание/вопрос собеседования). Тест: варианты, ключ, пояснение, сложность; задания семинаров и ИА — критерии (rubric) с баллами и уровнями.

- **Слайды** — минимум для одного модуля (обязательное требование), по умолчанию — для модуля/занятий, указанных в брифе (ТК-1: занятия 1 и 2; ТК-3: модуль pandas); темы слайдов берутся из учебного плана, поэтому совпадают по построению (V-REQ-01).

- **Аудитория-школьники**: упрощённый регистр, пояснение термина при первом упоминании (глоссарий отмечает «первое упоминание»), критерии «понятные подростку» (ТК1-5, ТК1-8).

- **Стажировка**: вместо лекций — задания СРС и вопросы собеседования с руководителем стажировки по каждому разделу; требования к отчёту и критерии защиты (ТК5-6, ТК5-7).

**1.** POST /edits с dry_run=true → разбор инструкции (LLM, схема EditIntent: цель, действие, параметры) → affected = dependency_graph.closure(target_ref) → ответ с планом (Д3 §4.5).

## 5.10. Актуализация старой программы (S22)

Старая программа загружается как файл роли old_program; S04 восстанавливает её структуру. S22 сопоставляет упомянутые инструменты и версии с service_catalog и PyPI (дата снимка в отчёте), LLM помечает устаревшие темы и предлагает замены. Результат — таблица «было → предлагается» с обоснованием; применённые изменения проходят обычный путь каркас → Human Gate → комплект.

## 5.11. Адаптация под аудиторию или объём (S23)

Создаётся программа-потомок (program.parent_id). При смене объёма веса модулей сохраняются, солвер пересчитывает часы под новый объём; при смене аудитории S06/S07 переформулируют РО и входные требования. Каркас потомка снова проходит Human Gate.
