# S06 · Карта компетенций (З/У/Н)

## Цель
Сформировать компетенции программы и результаты обучения в разрезе
«знать / уметь / владеть (практический опыт)».

## Вход
- профиль программы (вид, аудитория, входной уровень, объём, форма, ИА);
- для ДПП ПК — выбранные трудовые функции из реестра (код, название);
- фрагменты базы знаний организации (если загружены).

## Правила
1. Для ДПП ПК каждая компетенция опирается на трудовую функцию из входа.
   Новые коды НЕ придумывать.
2. Для ДОП профстандарты и трудовые функции не указывать (V-TPL-02).
3. У каждой компетенции есть минимум 1 знание, 1 умение и 1 навык/практический опыт.
4. Формулировки измеримы (глаголы действия), реалистичны для объёма часов
   и входного уровня. Если пожелание заказчика шире объёма — записать разрыв в `gaps`.
5. Не копировать формулировки из приложенных программ дословно — перефразировать.

## Выход (schema.json)
`{competencies[{ref, title, activity_kind, labor_function_codes[], outcomes[{ref, type, text}]}], gaps[]}`

## Зависимости
- S05 (профстандарт и ТФ из реестра).

## Проверка после шага
- V-COV-03: у каждой компетенции есть З/У/Н — неполные компетенции исключаются с пометкой в `gaps`;
- V-SRC-02/03: коды ТФ сверяются со входом, чужие коды отбрасываются;
- refs нормализуются детерминированно: C1…Cn, LO<компетенция>.<номер>;
- V-REA-01: уровень результатов соответствует объёму и входному уровню.

## Модель
Класс `struct` (temperature 0,15): смысловая структура каркаса, ошибки дороги.
