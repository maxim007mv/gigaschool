# S01 · Разбор брифа

## Цель
Превратить свободный текст запроса (и извлечённый текст файлов) в JSON-профиль
программы: аудитория, входной уровень, объём, форма, ограничения, пожелания.

## Вход
- `brief` — текст запроса заказчика (≤ 20 000 символов, Д4 §10);
- `files_text` — извлечённый текст приложенных файлов (может быть пустым);
- `answers` — уже имеющиеся ответы на уточняющие вопросы.

## Правила
1. Ничего не выдумывать: неизвестное поле остаётся пустым и попадает в `missing_slots`.
2. «Примерно месяц» — не объём; объём — только число академических часов.
3. Ограничения (кратность занятия, доля практики, СРС, ДОТ, режим дня) попадают
   в `constraints` только при явном упоминании в брифе.
4. Явные пожелания заказчика («сделать слайды», «без домашних заданий») — в `requested`.
5. Термины, требующие пояснения для аудитории, — в `glossary`.

## Выход (schema.json)
`{profile{audience, entry_level, schedule, duration_hint, notes, glossary, constraints},
goal, requested[], missing_slots[], assumptions[], gaps[], template_signs[]}`

## Зависимости
Нет — S01 открывает конвейер.

## Проверка после шага
- `missing_slots` содержит только известные слоты (kind, total_hours, audience,
  entry_level, form, final_attestation);
- `constraints` в допустимых диапазонах: кратность 1–8, ≤ 12 ч в день, 1–7 дней в неделю, доли 0–100 %;
- пустые строки нормализованы в `null`/`""`, glossary без пустых пар.

## Модель
Класс `struct` (структурная модель, temperature 0,15): S01 задаёт каркас остальных шагов.
