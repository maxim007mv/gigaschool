# S02 · Выбор шаблона программы

## Цель
Определить вид программы — `dpp_pk` (повышение квалификации) или `dop`
(общеразвивающая) — по признакам брифа; при неоднозначности решение принимает
LLM-арбитр с обоснованием (Д4 §5.1).

## Вход
- `brief` — текст запроса;
- `S01` — профиль и `template_signs` из разбора брифа;
- `attached_templates` — имена приложенных шаблонов (если есть).

## Правила (детерминированные, таблица 4.2)
1. Сильные признаки ДПП ПК: «повышение квалификации», «ДПП», «стажировка»,
   «удостоверение», работники/специалисты/учителя/госслужащие.
2. Сильные признаки ДОП: «общеразвивающая», «ДОП», школьники/дети/подростки,
   «кружок», «лагерь», профориентация.
3. Приложенный шаблон одного из видов — сильнейший признак (0,95).
4. Один сильный признак даёт уверенность 0,9; дополнительные — до 0,98.
5. Конфликт сильных признаков или уверенность < 0,8 → LLM-арбитр.
6. Полное отсутствие признаков → вопрос методисту (`question`), без вызова LLM.
7. «Студенты СПО/вуза» без явного вида — тоже вопрос.

## Выход (schema.json)
`{kind: dpp_pk|dop|null, confidence, source: rules|llm|question, reasons[], question}`

## Зависимости
- S01 (разбор брифа) — источник признаков.

## Проверка после шага
- при `source=rules` уверенность ≥ 0,8 и нет конфликта;
- при `source=question` LLM не вызывался;
- код вида всегда показывается методисту и может быть изменён (US-2).

## Модель
Правила + LLM-арбитр класса `struct` (temperature 0,15); LLM вызывается только при неоднозначности.
