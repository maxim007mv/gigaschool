# S18 · Верификация источников

## Цель
Проверить кандидатов источников и присвоить статус `verified | unverified |
not_found | outdated`. Неподтверждённые источники не удаляются и не выдаются за
проверенные: в .docx они получают пометку «[не подтверждено — проверьте]» (ЗАД-22).

## Вход
- `sources` из S17;
- `registries` — normative_acts, prof_standards, labor_functions, services;
- `today` — дата проверки (ISO), по умолчанию — текущая.

## Правила (таблица 4.5)
1. НПА: поиск в реестре по коду/номеру; проверка действия на дату программы;
   замена или истёкший срок → `outdated`; отсутствие в реестре → `not_found`.
2. Книга: контрольная цифра ISBN (10/13 знаков); неверная — `not_found`,
   верная без каталога библиотек — `unverified` («не подтверждено»).
3. Интернет-ресурс: HTTP-проверка в этом шаге не выполняется (заглушка allowlist) —
   статус `unverified` с записью в `evidence.http_checked=false`.
4. ПО и сервисы: каталог service_catalog — доступность в РФ, жизненный цикл;
   недоступно в РФ → `not_found`, цикл завершён → `outdated`.
5. Все проверки — детерминированные, без LLM и без сетевых вызовов.

## Выход (schema.json)
`{sources[{..., status, evidence}], summary{verified, unverified, not_found, outdated}, unconfirmed[], checked_at}`

## Зависимости
- S17 (кандидаты источников).

## Проверка после шага
- каждый источник получил ровно один статус и запись в `evidence`;
- `unconfirmed` перечисляет refs неподтверждённых источников для отчёта и .docx;
- контрольная цифра ISBN проверена алгоритмически (без внешних каталогов).

## Модель
Чистый код (`model_class=none`); LLM в верификации не участвует.
