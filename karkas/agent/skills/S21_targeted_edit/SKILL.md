# S21 · Точечная правка

## Цель
Применить инструкцию правки («усложни тест», «переименуй тему») к конкретному
элементу комплекта: разобрать инструкцию, вычислить затронутые элементы по графу
зависимостей, пометить их `stale` и вернуть план пересборки (Д4 §5.9).

## Вход
- `target_ref` — ref элемента (T2.3, Q-014, LO1.2, SL-T2.3 …);
- `instruction` — 3…2000 символов;
- `kit` (или `ctx.extra["kit"]`) — текущий комплект;
- `dry_run` — только план без применения (по умолчанию true).

## Правила
1. Затронутые элементы вычисляет `karkas.domain.dependency_graph.closure` —
   правила влияния (таблица 4.7) живут в домене.
2. Изменение часов темы/модуля возвращает каркас на повторный Human Gate;
   содержание остаётся, пока каркас не утверждён повторно.
3. Выход — план пересборки и комплект с `stale=true` у затронутых блоков;
   сама перегенерация выполняется навыками S11–S17 по плану.
4. Инструкция из 3…2000 символов (Д4 §10); пустой или гигантский ввод — ошибка.

## Выход (schema.json)
`{intent{action, target_ref, params, summary}, affected[], stale_refs[], plan[{ref, rebuild, reason}], dry_run, kit}`

## Зависимости
- S20 (актуальный комплект и выгрузки).

## Проверка после шага
- все refs плана существуют в комплекте; чужие refs не попадают в план;
- затронутые ContentBlock помечены `stale=true`; неизменные — не тронуты;
- при `dry_run=true` комплект возвращается без перегенерации, изменения не сохраняются.

## Модель
Класс `bulk` (temperature 0,5): разбор инструкции; граф влияния — детерминированный код.
