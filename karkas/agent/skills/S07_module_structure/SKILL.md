# S07 · Структура модулей и тем

## Цель
Построить модули и темы программы с весами, «практичностью», сложностью и
привязкой к результатам обучения. LLM предлагает только структуру — часы считает
детерминированный солвер S08 (AD-3).

## Вход
- компетенции и РО из S06;
- ограничения профиля (объём часов, форма, доля практики);
- пожелания брифа (число модулей, порядок тем).

## Правила
1. Каждая тема привязана минимум к одному РО (V-COV-04); чужие refs отбрасываются.
2. Веса модулей и тем > 0 (относительные, нормирует солвер); «практичность» 0…1,
   сложность 1…5, признак лабораторной — только при реальной лабораторной работе.
3. Темы упорядочены от базовых к сложным (V-SEQ-01: граф предпосылок по `complexity`).
4. Число тем реалистично для объёма: на 16 ч — единицы тем, а не десятки.
5. refs тем нормализуются детерминированно: M<номер>, T<модуль>.<тема>.

## Выход (schema.json)
`{modules[{ref, number, title, weight, att_form, topics[{ref, title, summary, outcome_refs[],
complexity, practicality, weight, has_lab}]}], gaps[]}`

## Зависимости
- S06 (карта компетенций и РО).

## Проверка после шага
- у каждой темы есть название, вес в диапазоне, привязка к существующим РО;
- модуль без валидных тем исключается с пометкой в `gaps`;
- связи «тема → РО» не выдуманы: refs сверены с выходом S06.

## Модель
Класс `struct` (temperature 0,15): структура влияет на часы и покрытие РО.
