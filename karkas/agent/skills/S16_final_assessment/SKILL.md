# S16 · Текущий контроль и итоговая аттестация

## Цель
Собрать оценочные средства завершения программы: вопросы собеседования, проект
или экзаменационные задания — с критериями и привязкой к РО. Для стажировки —
вопросы руководителя стажировки и требования к отчёту (ТК5-6, ТК5-7).

## Вход
- `form` — форма итоговой аттестации из каркаса (защита проекта, экзамен, собеседование);
- `outcomes` — результаты обучения программы;
- `profile` — профиль аудитории;
- `kind` — вид программы (для стажировки — свой набор средств).

## Правила
1. `final_project`, `exam_task` и `portfolio_item` обязаны иметь rubric (критерии с баллами).
2. `interview_question` обязан иметь `outcome_refs`, rubric — желателен.
3. Вопросы/задания — по РО программы; формулировки авторские.
4. Для каждого РО — минимум 2 оценочных средства за всю программу
   (MIN_ASSESSMENTS_PER_OUTCOME; видно в покрытии S19).

## Выход (schema.json)
`{items[{ref, kind, stem, rubric[{criterion, max_points, levels[]}], outcome_refs[]}],
requirements[], form, notes}`

## Зависимости
- S10 (проверенный каркас).

## Проверка после шага
- проект/экзамен без критериев — отбрасываются в `dropped`;
- элементы без РО отбрасываются; refs: `FA-1`, `FA-2`, …;
- формы итоговой аттестации совпадают с каркасом (V-REQ-01).

## Модель
Класс `bulk` (temperature 0,5); требования к отчёту стажировки — текстом в `requirements`.
