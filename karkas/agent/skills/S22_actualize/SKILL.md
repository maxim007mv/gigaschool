# S22 · Актуализация старой программы

## Цель
Найти устаревшие темы, инструменты и ссылки в старой программе и предложить
замены: таблица «было → предлагается» с обоснованием (Д4 §5.10). Применённые
изменения проходят обычный путь «каркас → Human Gate → комплект».

## Вход
- `old_program` (или `S04`) — восстановленная структура старой программы;
- `tools` — упомянутые инструменты и версии;
- `service_catalog` — каталог сервисов (доступность в РФ, жизненный цикл);
- `snapshot_date` — дата снимка каталогов (по умолчанию — сегодня).

## Правила
1. Сопоставление инструментов с каталогом и снимком версий — часть ответа;
   дата снимка обязательно фиксируется в отчёте.
2. Устаревшее не удаляется молча: каждая замена — с обоснованием.
3. Инструменты, недоступные в РФ или снятые с жизненного цикла, обязаны попасть
   в `outdated` (детерминированная проверка по каталогу дополняет LLM).
4. Устаревшие темы не переписываются автоматически — предложения показываются методисту.
5. Замены не должны ломать результаты обучения без повторной проверки покрытия (S19).

## Выход (schema.json)
`{outdated[{element, current, reason}], proposals[{was, proposed, rationale}], snapshot_date, notes}`

## Зависимости
- S04 (структура старой программы из анализа референсов).

## Проверка после шага
- proposals без rationale отбрасываются; дубли по «was» удаляются;
- инструменты с lifecycle ≠ current из каталога добавлены в `outdated`;
- `snapshot_date` заполнена и совпадает с переданной датой.

## Модель
Класс `struct` (temperature 0,15): сопоставление версий и терминов требует точности.
