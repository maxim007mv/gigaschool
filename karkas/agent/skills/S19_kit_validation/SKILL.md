# S19 · Самопроверка комплекта

## Цель
Полная автопроверка собранного комплекта KitV1: часы, покрытие РО оценочными
средствами, источники, шаблон, заимствования, ограничения. Отчёт является
обязательным приложением к комплекту (GET /report).

## Вход
- `kit` (или `ctx.extra["kit"]`) — полный комплект (каркас + содержание + источники);
- `registries` — реестры НПА/профстандартов/ТФ/сервисов;
- `reference_texts`, `declared_totals` — для V-PLG-01 и V-SMP-01;
- `today` — дата проверки (ISO), по умолчанию — текущая.

## Правила
1. Полный прогон `karkas.domain.validators.run_validation` — те же правила V-*,
   что и в S10, но по всему комплекту (включая содержание и источники).
2. Отчёт собирается в каноническую модель `Report` (версия, summary, issues, gaps).
3. Ошибки не замалчиваются: неподтверждённые источники перечислены,
   допущения и находки образца сохранены отдельными списками.
4. Смысловые LLM-проверки — расширение поверх доменных правил (Д1 §7, S19 struct).

## Выход (schema.json)
`{report{passed, version, duration_ms, summary, issues[], gaps[], sample_findings[], assumptions[]}, passed, error_count}`

## Зависимости
- S18 (статусы источников), S16 (ИА), S15, S14, S13 (оценочные средства и содержание).

## Проверка после шага
- V-COV-02: каждый РО подтверждён минимум 2 оценочными средствами;
- V-SRC-04: литература помечена «не подтверждено», если не подтверждена;
- V-TPL-01…03: обязательные разделы, правила вида программы, пустые плейсхолдеры;
- `passed=false` при любой ошибке уровня error.

## Модель
Ядро — детерминированный код; смысловая LLM-проверка выполняется структурной моделью опционально.
