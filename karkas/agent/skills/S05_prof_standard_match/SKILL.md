# S05 · Подбор профстандарта и трудовых функций

## Цель
Выбрать профстандарт и трудовые функции для программы ДПП ПК — строго из реестра
(коды не выдумываются: V-SRC-02/03, ТК1-9).

## Вход
- `kind` — вид программы (dpp_pk/dop) из S02;
- `profile` — профиль из S01;
- `candidates` — кандидаты из реестра: `{code, title, status, labor_functions[]}`;
- `attached_ps` — профстандарт из приложенного файла (если есть).

## Правила (Д4 §5.3)
1. Шаг выполняется только для dpp_pk; для ДОП возвращается пустой результат (V-TPL-02).
2. Если профстандарт приложен — его код и ТФ сверяются с реестром (LLM не нужен).
3. Иначе LLM ранжирует ТОЛЬКО кандидатов и выбирает профстандарт и ТФ.
4. Код профстандарта обязан быть среди кандидатов со статусом `active`;
   коды ТФ — среди ТФ выбранного профстандарта. Остальное отбрасывается.
5. Если подходящего нет — пустой результат и пометка «требуется выбор методиста».

## Выход (schema.json)
`{prof_standard{code,title}|null, labor_functions[{code,title}], confidence, note, dropped_codes[]}`

## Зависимости
- S01 (разбор брифа).

## Проверка после шага
- код ПС ∈ кандидатам со статусом active, иначе результат пуст;
- коды ТФ ⊆ реестра; отброшенные коды перечислены в `dropped_codes`;
- для ДОП ссылки на профстандарт отсутствуют.

## Модель
Класс `struct` (temperature 0,15). Для ДОП и приложенного профстандарта LLM не вызывается.
