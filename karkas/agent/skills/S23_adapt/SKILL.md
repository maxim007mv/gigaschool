# S23 · Адаптация под аудиторию или объём

## Цель
Создать программу-потомок (`program.parent_id`): при смене объёма веса модулей
сохраняются, солвер пересчитывает часы; при смене аудитории результаты обучения
переформулируются под новый уровень (Д4 §5.11).

## Вход
- `modules` — структура модулей и тем (веса, практичность) из каркаса родителя;
- `new_constraints` — новый объём и ограничения (`total`, `unit`, доли, СДО);
- `new_audience` — описание новой аудитории (может отсутствовать);
- `outcomes` — текущие РО для переформулировки.

## Правила
1. Часы пересчитывает ТОЛЬКО `karkas.domain.hours.solve/rebalance`; веса модулей
   и «практичность» при смене объёма сохраняются.
2. Новый каркас потомка повторно проходит Human Gate (решение принимает методист).
3. При смене аудитории РО переформулируются: уровень, примеры, регистр — но
   сохраняются измеримость и типы (знать/уметь/владеть).
4. Ref`ы сохраняются по возможности; новые связи с темами проверяет S19.

## Выход (schema.json)
`{child{total_hours, rows{}, distance{}, module_of{}, proof[]}, outcomes[{ref, type, text}],
assumptions[], notes}`

## Зависимости
- S08 (солвер часов; веса берутся из каркаса родителя).

## Проверка после шага
- V-HRS-01: Σ строк + ИА = новый объём (доказательства солвера в `proof`);
- при смене объёма веса модулей не изменились;
- РО: непустые тексты, тип из knowledge|skill|experience, ref`ы формата LOd.d;
- допущения (например, «веса сохранены») записаны в `assumptions`.

## Модель
Класс `bulk` (temperature 0,5) — только для переформулировки РО; часы считает солвер.
