## Как сдавать (Памятка)
- «Код на машине не попадает на проверку автоматически — закоммитьте и запушьте его в ветку main репозитория команды в Gitea.» (cd ~/project; git add -A; git commit; git push origin main). Gitea только по HTTP с паролем команды.
- «На стоп-коде (29.10, 00:01) репозиторий замораживается: на проверку уходит последний коммит, попавший в main до этого момента. Коммиты, оставшиеся только на машине, не учитываются.»
- «Работа производится в рамках одного репозитория. Не создавайте новые - все сервисы и модули публикуйте в репозитории, который вам выдал»
- «История не оценивается: число коммитов, их сообщения и авторы на баллы не влияют — важно только то, что лежит в main.»
- Совет: «Напишите README: что делает решение, как его запустить и где демо. Данные держите вне git или в форматах, которые проверка не читает.» «Не храните в репозитории датасеты и ключи доступа».
- Автопроверка: «С 18.10 каждый день с 06:00 до 10:00 (МСК) организатор запускает прогоны автопроверки по всем командам... проверяется репозиторий команды в Gitea — последний коммит ветки main на момент запуска.» «В момент запуска push в репозиторий закрывается... Когда проверены все команды, push открывается сам». «Запустить проверку самим нельзя: самопроверка на этом хакатоне выключена». «Делайте git push до 06:00».
- Демо: приложение на порту 8000 (слушать 0.0.0.0:8000) — по адресу команды; эксперты/жюри открывают его во время звонка/защиты. Порты 8888, 8088, 8089 заняты.
- Карточка решения (капитан, Сводка → «Решение»): описание до 8000 символов (Markdown не поддерживается, https:// ссылки кликабельны) + «Ссылка на решение» (по умолчанию адрес сервера команды). Жюри читает карточку перед защитой. Сейчас у нас в «Своя ссылка на решение» стоит Google Doc (https://docs.google.com/document/d/1FJCOyZ_a6yhGSTSqz_BPsz2ZbvxZuRD9hOvPbYqc6pI/edit?usp=sharing) — Памятка советует поставить туда демо/репо/презентацию.
- После стоп-кода: репозитории в архив, поля карточки read-only, запись на звонки/прогоны/перезагрузка ВМ недоступны, «До публикации итогов лидерборд скрывает от участников баллы и места.» Совет: финальный push за 15–30 минут до стоп-кода.

## Кейс №1 — текст страницы (ключевое, дословно)
«Создайте ИИ-агента, который по запросу пользователя разрабатывает программу обучения по ИИ и формирует полный комплект материалов для курса. Решение должно учитывать заданные требования и референсы, определять структуру обучения, формировать карту компетенций, тестовые вопросы и задания для семинаров, а также готовить план и визуальные материалы для лекций.»
«Вам предстоит за десять дней собрать ИИ-агента, который по запросу методиста создает образовательную программу по любому ИТ-направлению и на любой объем часов. Программа должна быть оформлена по шаблону Академии цифрового развития (АЦР) и сопровождаться полным комплектом материалов (картой компетенций, учебным планом, тестами, заданиями для семинаров, планами и слайдами лекций).»
Проблема: «Одну программу сегодня собирают вручную от двух до восьми недель»; ошибки в арифметике часов («модуль заявлен как 246 часов самостоятельной работы, а в итоговой строке появляются 66 часов практик и 6 часов лабораторных, хотя контактная работа указана как ноль часов»); нет связи результатов обучения, тем и вопросов аттестации; два разных шаблона (ПК и общеразвивающая).
### 3. Целевой сценарий (методист — основной пользователь)
1. Методист описывает задачу свободным текстом («программа повышения квалификации на 72 часа по анализу данных на Python для сотрудников банков, очно-заочная форма, итоговая аттестация в виде защиты проекта») и прикладывает референсы (прошлая программа, профстандарт, ссылки).
2. Агент определяет, какой из двух шаблонов АЦР подходит, и задает уточняющие вопросы, если не хватает сведений об аудитории, входном уровне, объёме или форме аттестации.
3. Агент предлагает каркас: цель, карта компетенций (знания/умения/навыки), учебный план, где часы по модулям, темам и видам работы «в сумме дают ровно запрошенный объем».
4. Методист правит или утверждает каркас, и только после этого агент переходит к содержанию.
5. Комплект: рабочие программы модулей, тестовые вопросы с ключами, задания для семинаров с критериями оценки, планы лекций со слайдами, список литературы.
6. Самопроверка: суммы часов, покрытие каждой компетенции темами и вопросами, существование источников, полнота разделов шаблона.
7. Точечная правка («заменить тему 2.3», «усложнить тест») — пересобирается только затронутое.
8. Выгрузка: программа .docx, слайды .pptx, тесты в формате для загрузки в LMS.
### 4. Функциональные ограничения
«Ваше решение работает на инфраструктуре Cloud.ru и выдает черновик, который в итоге утверждает человек.»
«Языковые модели и эмбеддинги берутся из каталога Cloud.ru Evolution Foundation Models, где доступны GigaChat, Qwen, DeepSeek и другие модели. Зарубежные API вроде OpenAI, Anthropic или Google использовать нельзя. Решение разворачивается в выданной среде и вызывается через единый API-эндпоинт, чтобы его можно было проверить на наборе тестовых запросов.»
«Рекомендуем строить агента по тому же принципу, что и в GigaCowork, то есть описывать каждый шаг как отдельный навык с понятной инструкцией.»
«Агент должен справляться с программой любого объема, от коротких интенсивов на 16 часов до программ на несколько сотен часов. Каркас любой программы собирается не дольше трёх минут, полный комплект для программы на 72 часа не дольше 20 минут.»
«Человек остается в контуре на ключевых шагах. Методист утверждает цель, компетенции и часы до того, как агент начнет генерировать содержание. Агент не выпускает финальный документ, поэтому реквизиты приказа, ФИО преподавателей и подписи остаются полями для заполнения. Любую часть комплекта можно переделать отдельно, не нарушая согласованность остального.»
«Программы повышения квалификации опираются на 273-ФЗ и приказ Минобрнауки № 499, а компетенции в них связываются с действующими профстандартами и кодами трудовых функций. Общеразвивающие программы опираются на приказ Минпросвещения № 629. Материалы готовятся на русском языке и выгружаются в .docx и в .pptx, а все данные комплекта дополнительно сохраняются в JSON.»
«Заведомо неприемлемы выдуманные источники, приказы и номера профстандартов, поэтому неподтвержденный источник агент должен явно помечать. Нельзя дословно копировать чужие курсы и референсы. Не подходит и решение, при котором один промпт сразу выдает документ без проверки согласованности, потому что так сегодня умеет любой чат-бот.»

«Мы ждем от вас веб-сервис или чат-интерфейс, внутри которого работает агентная логика с отдельными шагами для структуры, содержания и проверки. Ключевая метрика успеха – методист получает комплект, который достаточно поправить за несколько часов, вместо того чтобы переписывать его неделями. Согласованность и достоверность здесь важнее красоты слайдов.»
