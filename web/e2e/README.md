# E2E-сценарии КАРКАС (Playwright)

Пять открытых тест-кейсов запускаются как сквозные сценарии на стенде
с записанными ответами моделей (Д3 §11: «Playwright e2e: 5 открытых тест-кейсов
как сценарии (бриф → вопросы → каркас → утверждение → комплект → выгрузка)»).

Сами тесты здесь пока не лежат — это описание будущего набора. Каждый сценарий
дополняется проверкой доступности axe-core и снимком для визуальной регрессии.

## Общая подготовка

- Стенд поднимает backend с записанными «кассетами» ответов моделей
  (pytest-recording, см. Д4 §11) — прогон детерминированный.
- Пользователь: методист АЦР; для сценария 5 — руководитель (утверждение).
- Общие проверки на каждом экране: `axe-core` — 0 критичных нарушений;
  клавиатурная доступность таблицы часов (стрелки/Tab/Enter).

## Сценарий 1. Полный цикл (ТК-2, «ИИ для учителя», 36 ч)

1. `/programs/new`: ввести бриф, приложить шаблон ДПП (роль «Шаблон»).
2. Уточнения: ответить кнопками на все вопросы, один — «На ваше усмотрение».
3. Каркас → «Учебный план»: Σ тем + ИА = 36; часы не правятся, утверждение доступно.
4. «Утвердить каркас» → статус «Каркас утверждён».
5. Комплект: дождаться SSE `kit_ready`, проверить отчёт самопроверки (passed).
6. Выгрузка: `.docx`, `GIFT`, `.json` — файлы готовы, ссылки живые.

Ожидания: Human Gate до шага 4 закрыт (409 GATE_NOT_PASSED при попытке
собрать комплект); в списке программ бейдж статуса меняется по шагам.

## Сценарий 2. «Найди и исправь ошибку в часах за 1 минуту»

1. Открыть каркас с намеренно испорченными часами (фикстура: тема T2.1
   увеличена на 2 ч).
2. Убедиться: подсветка итога, текст «Сумма часов программы — 38 ч, а объём — 36 ч»,
   кнопка «Утвердить каркас» неактивна, причина рядом.
3. Исправить часы в ячейке — подсветка исчезает мгновенно (живой пересчёт ≤ 1 с).
4. «Сохранить часы» → сервер подтверждает версию, ошибок нет, утверждение доступно.

Метрика: время от открытия экрана до исправления — не более 60 секунд (Д3 §11).

## Сценарий 3. Неполный запрос (ТК-4, «Кибербезопасность»)

1. Бриф: «примерно на месяц», без часов и типа программы.
2. Уточнения: показано не более 5 карточек; карточка «Агент заметил» объясняет
   разрыв «месяц ≈ 16–32 часа».
3. Ответ «На ваше усмотрение» → пункт появляется в допущениях отчёта.
4. До ответа на обязательные слоты каркас не собирается (409 CLARIFICATION_REQUIRED).

## Сценарий 4. Точечная правка с dry_run (US-7)

1. Открыть комплект, выбрать тему T2.3.
2. «Точечная правка»: инструкция «Замени тему на „Работа с датами“, часы оставь».
3. «Показать, что изменится» — видны списки «Будет пересобрано» (8 элементов)
   и «Не изменится» (часы, компетенции, другие модули).
4. «Применить» → diff-сводка изменённых ref; содержимое остальных тем не изменилось.
5. Отчёт самопроверки пересчитан; покрытие не нарушено.

## Сценарий 5. Стажировка без аудиторных часов (ТК-5, DevOps, 256 ч)

1. Бриф/ответы: стажировка, 256 ч, 64 дня по ≤ 4 ч.
2. Каркас: все строки «ЛК = ПР = ЛБ = 0», СРС = 254, ИА = 2.
3. Роль руководителя: «Утвердить каркас» доступна; у эксперта — скрыта
   с подсказкой «Утверждает методист или руководитель».
4. Комплект: у каждого модуля есть вопросы собеседования, критерии защиты отчёта.

## Инфраструктурные требования

- `@playwright/test` + `@axe-core/playwright`; запуск в CI против staging-стенда.
- Хранение эталонных скриншотов — по экранам (список программ, каркас, комплект).
- Селекторы — по ролям и доступным именам (`getByRole`, `getByLabel`), не по CSS-классам.
